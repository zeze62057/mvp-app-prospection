# Vidéo : Le workflow Plan, Execute, Validate

Module 1, section 2 « La Méthode », chapitre 3. Sources : `02-methode.md`, chapitre 3, et `02-methode-prompts.md`, partie 2.
Format : écran filmé avec voix off. Adresse aux élèves : vouvoiement.

## 1. Cadrage

- **Objectif d'apprentissage** : à la fin, l'élève sait dérouler les trois temps Plan, Execute, Validate sur une tâche, sait pourquoi il ne faut sauter aucun des deux raccourcis dangereux, et l'a vu faire sur une vraie tâche.
- **Signal de réussite** : l'étape 2 du guide de réussite demande de « refaire une tâche en 3 temps explicites : Plan (demandé et lu avant tout code), Execute, Validate ». La démonstration le montre de bout en bout.
- **Prérequis de l'élève** : avoir suivi les chapitres 1 et 2 de la section 2.
- **Durée cible** : entre 7 et 10 minutes.
- **Exemple concret qui porte la vidéo** : ajouter une page « Tarifs » au site vitrine d'un artisan, en trois temps (« Exemple bout en bout » de la fiche pratique), après l'exemple du formulaire d'intake du projet fil rouge.

## 2. Points à valider avec Zézé avant d'enregistrer

Le chapitre du cours est écrit pour Zézé, pas pour des élèves. Rien n'y renvoie à votre workspace : il n'y a donc pas de passage remplacé. Quatre points demandent votre décision. Les « tu » du cours deviennent des « vous ».

1. **L'exemple du projet fil rouge.** Le cours cite « le projet fil rouge Alpha Conseil (section 5) », avec Playwright pour la validation. Alpha Conseil est le projet fil rouge du cours : les élèves le rencontrent en section 5. Le passage est gardé. Playwright n'ayant pas encore été présenté à ce stade, le script dit que l'élève le verra en section 5. À confirmer.
2. **La démonstration de la page « Tarifs ».** Elle reprend mot pour mot les trois prompts de l'« Exemple bout en bout » de la fiche pratique (le plan, « Le plan me va, vas-y. », puis la validation). Elle utilise le site fictif `livrables/formations/ecosysteme-ia/_ressources-demo/site-artisan/`, que j'ai écrit : **il n'est pas dans le cours**. À valider, ou à remplacer par un site à vous.
3. **La vérification dans le navigateur.** Le prompt de validation demande à Claude Code d'« ouvrir tarifs.html dans le navigateur pour vérifier que le menu fonctionne ». Or l'outil qui permet à Claude Code de piloter un navigateur (Playwright) n'est présenté qu'en section 5. Sans lui, Claude Code peut au mieux ouvrir le fichier, pas cliquer dans le menu. Le script ne prétend donc pas qu'il a testé le menu : vous regardez la page vous-même et vous dites ce que vous voyez. **Répétez ce passage avant d'enregistrer.** Si le résultat ne convient pas, on peut garder le prompt du cours et commenter honnêtement ce que Claude Code a pu ou non vérifier.
4. **Le plan n'est pas prévisible.** Claude Code peut proposer un plan différent de celui que le cours imagine (par exemple créer un nouveau fichier de style). La fiche prévoit ce cas : si une étape ne vous convient pas, corrigez-la avec le prompt « Le plan me va sauf l'étape 3 : réutilise style.css existant plutôt que d'en créer un nouveau. Le reste est bon, vas-y. ». Le script dit « Si le plan me convient… sinon, je corrige d'abord l'étape concernée » : il ne présume pas du plan.

## 4. Durée estimée

**652 mots prononcés**, soit environ 4,7 minutes de voix, plus 230 secondes de manipulation à l'écran. **Durée estimée : 8:29**, avant coupes au montage.

Le rythme de 140 mots par minute est une hypothèse. Après le premier enregistrement, corrigez-le avec votre débit réel. Les temps de manipulation de la démonstration (80 s, 70 s et 80 s) sont des estimations : l'attente de Claude Code se coupe au montage.

## 5. Relecture de fidélité

Chaque affirmation du script a été comparée au chapitre source et à la fiche pratique : la structure centrale en trois temps ; le Plan (lisible sans connaissance technique, correction peu coûteuse) ; Execute (par étapes, phase spectaculaire mais peu déterminante) ; Validate (test manuel, vérification automatisée ou relecture ciblée) ; l'exemple du formulaire d'intake ; les deux raccourcis dangereux ; l'application à toute taille de tâche ; les trois points clés. La démonstration reprend les trois prompts de l'« Exemple bout en bout » de la fiche. Écarts : l'ajout « un outil que vous découvrirez en section 5 » pour Playwright (point 1), et la formule conditionnelle « si le plan me convient » (point 4).
