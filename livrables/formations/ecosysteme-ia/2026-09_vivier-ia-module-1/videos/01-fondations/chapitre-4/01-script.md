# Vidéo : Vercel et OVH, mettre en ligne en quelques minutes

Module 1, section 1 « Les Fondations », chapitre 4. Source : `01-fondations.md`, chapitre 4.
Format : écran filmé avec voix off. Adresse aux élèves : vouvoiement.

## 1. Cadrage

- **Objectif d'apprentissage** : à la fin, l'élève sait à quoi servent Vercel et OVH, sait choisir entre les deux selon le projet, et sait déployer une page sur Vercel.
- **Signal de réussite** : l'élève obtient par lui-même une adresse publique qui fonctionne, même si le contenu de la page est insignifiant. C'est le signal de passage de l'étape 1 du guide de réussite, qui demande de « déployer n'importe quoi de minimal sur Vercel (une seule page suffit) ».
- **Prérequis de l'élève** : avoir suivi les chapitres 1 à 3 (Claude Code, VS Code, Git et un compte GitHub avec un dépôt).
- **Durée cible** : entre 6 et 9 minutes.
- **Exemple concret qui porte la vidéo** : un site vitrine, surtout statique, déployé automatiquement à chaque push GitHub sur Vercel, face à un backend n8n auto-hébergé qui a sa place sur OVH.

## 2. Points à valider avec Zézé avant d'enregistrer

Le chapitre du cours est écrit pour Zézé, pas pour des élèves. Un passage a été adapté, un autre est à confirmer, et deux points demandent votre décision. Rien d'autre n'a été changé sur le fond.

1. **Une affirmation à vérifier avant de la dire à des élèves.** Le cours dit qu'OVH est utile pour des « données hébergées en Europe ou en Afrique selon les besoins du client ». Je n'ai pas pu vérifier que OVH propose un hébergement en Afrique. Dans le script, la phrase devient « l'hébergement des données dans la région exigée par le client ». Si vous confirmez l'Afrique après vérification sur le site d'OVH, on rétablit le texte d'origine.
2. **L'exemple concret** dit dans le cours : « Un site vitrine pour Vivier IA, principalement statique, avec un déploiement automatique à chaque push GitHub, est un bon candidat pour Vercel. » Le script le garde tel quel : Vivier IA est le nom de l'école des élèves, pas un projet personnel. Le renvoi au « Module 2 » pour le backend n8n est gardé aussi. Dites-moi si vous préférez un exemple plus général (« un site vitrine »).
3. **La démonstration du déploiement sur Vercel.** Le cours donne les étapes, pas la page à déployer. Le guide de réussite demande pourtant de vivre le trajet complet jusqu'à une adresse publique, et c'est l'image forte de la vidéo. Proposition : déployer une page minimale, avec un compte GitHub et un compte Vercel de démonstration. La page se prépare la veille, en demandant à Claude Code : « Crée une page HTML minimale avec un titre et une phrase. » **Cette demande n'est pas dans le cours**, et il faut la valider. Le dépôt doit exister et contenir la page avant l'enregistrement : le chapitre 3 n'a pas montré la connexion à GitHub ni le push, donc l'élève ne l'a pas vue à l'écran. L'adresse obtenue sera publique : supprimez le projet Vercel et le dépôt de démonstration après l'enregistrement. Autre option : raconter le déploiement sans le faire, avec seulement le tableau de bord. Je recommande la démonstration réelle, parce que le signal de passage est justement d'obtenir une adresse publique.
4. **Les libellés d'interface et l'achat chez OVH.** Le cours cite « Add New Project » sur Vercel, et les noms des offres d'OVH. Ces écrans changent souvent : à vérifier à l'écran le jour de l'enregistrement, et à corriger dans la diapositive 5 si le libellé a changé. Pour OVH, le script montre seulement le site et la page des offres : **aucun achat, aucune commande, aucune information de paiement ni de vraie identité à l'écran.** Le cours ne donne pas de prix : le script n'en cite aucun.

## 4. Durée estimée

**571 mots prononcés**, soit environ 4,1 minutes de voix, plus 130 secondes de manipulation à l'écran. **Durée estimée : 6:15**, avant coupes au montage.

Le rythme de 140 mots par minute est une hypothèse. Après le premier enregistrement, corrigez-le avec votre débit réel. Le temps de déploiement sur Vercel (quelques dizaines de secondes en général) est une estimation à ajuster.

## 5. Relecture de fidélité

Chaque affirmation et chaque nom du script a été comparé au chapitre source : le rôle de l'hébergement et du déploiement ; Vercel (sites et applications web modernes, déploiement souvent automatisé dès qu'un changement est poussé sur GitHub, projets rapides, MVP, sites vitrines, front-end) ; OVH (hébergeur plus traditionnel, serveur dédié, base de données auto-hébergée, contraintes spécifiques, coûts maîtrisés sur la durée) ; le choix selon le projet ; l'exemple concret (site vitrine, backend n8n, Docker, workers, stockage) ; les quatre étapes Vercel et les deux étapes OVH, avec l'hébergement mutualisé, le VPS et le renvoi au Module 2, section 5 ; les trois points clés ; « un projet n'est livré que lorsqu'il est en ligne ». Écarts : la phrase sur l'Afrique (point 1 de la section 2), et trois définitions ajoutées à l'oral pour ne laisser aucun terme sans explication : « MVP », « front-end » (dit « la partie visible des applications ») et « statique » (« VPS » est déjà défini dans le cours). La démonstration du déploiement ajoute la mise en scène décrite au point 3 de la section 2, sans commande nouvelle.
