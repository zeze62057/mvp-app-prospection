# Vidéo : Git et GitHub, le filet de sécurité du code

Module 1, section 1 « Les Fondations », chapitre 3. Source : `01-fondations.md`, chapitre 3.
Format : écran filmé avec voix off. Adresse aux élèves : vouvoiement.

## 1. Cadrage

- **Objectif d'apprentissage** : à la fin, l'élève sait ce que sont Git et GitHub, pourquoi ils protègent son projet, les trois réflexes à prendre, et il a fait un premier commit sur son dossier.
- **Signal de réussite** : un premier commit Git existe sur le dossier de l'élève, même avec un seul fichier dedans. C'est la deuxième action du guide de réussite (étape 1).
- **Prérequis de l'élève** : avoir suivi les chapitres 1 et 2 (Claude Code installé, VS Code et son terminal ouverts sur un dossier).
- **Durée cible** : entre 6 et 9 minutes. Le chapitre est dense : deux notions, trois réflexes, deux installations.
- **Exemple concret qui porte la vidéo** : le jour où une modification casse un fichier important, revenir à la version d'avant prend quelques secondes, grâce à l'historique.

## 2. Points à valider avec Zézé avant d'enregistrer

Le chapitre du cours est écrit pour Zézé, pas pour des élèves. Un passage a été adapté, et trois points demandent votre décision. Rien d'autre n'a été changé sur le fond. Les seules retouches de forme : « Ton Nom » et « ton.email@exemple.com » deviennent « Votre Nom » et « votre.email@exemple.com » (vouvoiement).

1. **L'exemple concret** dit dans le cours : « C'est exactement le fonctionnement du Slash Command `/commit` de ce workspace : avant chaque commit, une vérification qu'aucun fichier sensible comme `.env` n'est inclus, un message clair qui explique le pourquoi, et jamais de push sans validation explicite de ta part. » La commande `/commit` n'existe que dans votre workspace, les élèves ne l'ont pas. Dans le script, le passage garde les trois réflexes du cours (aucun fichier sensible, message clair, jamais de push sans validation) sans nommer `/commit`. Le principe est identique.
2. **La démonstration du premier commit.** Le cours ne donne aucune commande pour créer le dépôt, faire le commit, ni le connecter à GitHub. Il dit seulement que « Claude Code peut faire cette partie techniquement pour toi, avec `/commit` puis `git push` », ce qui repose encore sur `/commit`. Le script n'invente donc aucune commande : vous demandez à Claude Code de faire le commit, vous lisez ce qu'il propose, vous validez. **La demande à taper n'est pas dans le cours.** Proposition à valider ou à corriger : « Fais le premier commit de ce dossier avec un message clair. Vérifie d'abord qu'aucun fichier sensible n'est inclus. Ne pousse rien. » Autre décision : la connexion à GitHub et le push sont seulement racontés, pas montrés, parce qu'ils demandent un vrai dépôt et un jeton. Si vous voulez les montrer, il faut un dépôt de démonstration vide que vous supprimez ensuite, et un accord sur le déroulé exact.
3. **La configuration globale de Git.** Les deux commandes `git config --global` du cours modifient la configuration de votre poste, où votre nom et votre adresse e-mail sont déjà enregistrés. Les taper à l'écran avec des valeurs d'exemple les écraserait. Et les taper avec les vraies afficherait votre adresse e-mail. Le script affiche donc les deux commandes sur la diapositive, sans les exécuter. Si vous voulez les exécuter, faites-le dans un profil Windows de démonstration.
4. **Le jeton GitHub est un secret.** Le cours cite le chemin (Settings, Developer settings, Personal access tokens). Un jeton ne s'affiche qu'une fois, à sa création, et il ne doit jamais apparaître à l'écran. Le script cite le chemin sans créer de jeton pendant l'enregistrement. Si vous voulez le montrer en vrai, il faudra le révoquer aussitôt après.

**615 mots prononcés**, soit environ 4,4 minutes de voix, plus 125 secondes de manipulation à l'écran. **Durée estimée : 6:29**, avant coupes au montage.

## 5. Relecture de fidélité

Chaque affirmation et chaque nom du script a été comparé au chapitre source : Git garde en mémoire chaque état du projet sous forme de commits, « photos datées du code à un instant donné » ; GitHub héberge ces historiques, les partage, les sauvegarde et permet de collaborer ; le filet de sécurité (revenir à un état antérieur, sans Git une erreur peut être irréversible, avec Git presque rien n'est perdu définitivement) ; les trois réflexes ; la validation finale avant un push ; l'exemple concret adapté (section 2, point 1) ; l'installation sous Windows, Mac et Linux avec `git --version` et `sudo apt install git` ; les deux commandes `git config --global` ; le compte gratuit, le dépôt vide, la connexion et le premier commit poussé, le jeton d'accès personnel et son chemin ; les trois points clés. Deux mentions de prononciation s'y ajoutent : « point env » pour `.env` et « tiret tiret version » pour `--version`, qui se disent ainsi à l'oral. La démonstration du premier commit ajoute la mise en scène décrite au point 2 de la section 2, sans commande nouvelle.
